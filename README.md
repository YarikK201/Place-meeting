# Место встречи

MAX-бот помогает школьникам Кузбасса находить мероприятия и людей со схожими
интересами. Педагоги предлагают события, а модераторы проверяют заявки и жалобы.

## Возможности

- Каталог, избранное и фильтры по тематике, возрасту, городу, дате и формату.
- Пошаговая анкета школьника: город, возраст, интересы и навыки; публикация и скрытие.
- Поиск школьников, заявки в друзья, разговоры и личные сообщения.
- Подтверждение педагогов, создание и редактирование мероприятий через модерацию.
- Модерация педагогов, мероприятий, жалоб и заявок на смену роли.
- Приветствие с кнопками по событию MAX «Начать»; `/start` возвращает в главное меню.

## Технологии

Python 3.12, `maxapi==1.2.3`, MAX API, SQLite и Docker Compose V2.
Бот получает события через **Long Polling**: публичный сервер, домен и открытые
порты не нужны. Для одного токена запускайте только **один экземпляр** бота.
Не подключайте к нему параллельно другой polling-процесс или webhook.

Прямые зависимости и версии находятся в `requirements.txt`, транзитивные версии —
в `constraints.txt`. `tzdata` обеспечивает часовые пояса при запуске на Windows.
Базовый Python-образ закреплён по digest. Системные пакеты устанавливаются из
репозитория Debian, поэтому сборка не обещает побайтовой идентичности.

## Быстрый запуск на Windows

Установите [Git](https://git-scm.com/downloads) и
[Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).
Запустите Docker Desktop в режиме Linux containers с WSL 2.
Получите токен своего тестового бота через платформу MAX по
[официальной инструкции](https://dev.max.ru/docs-api). Реальный токен не нужен
для автоматических тестов и сборки.

Откройте PowerShell:

```powershell
git clone --branch dev https://github.com/YarikK201/Place-meeting.git
cd Place-meeting
Copy-Item .env.example .env
notepad .env
```

В `.env` замените образцы на свои значения:

```dotenv
MAX_BOT_TOKEN=ВАШ_ТОКЕН_MAX
MODERATOR_ACCESS_CODE=ВАШ_СЕКРЕТНЫЙ_КОД_НЕ_КОРОЧЕ_12_СИМВОЛОВ
```

Для кода используйте случайную длинную строку, известную только проверяющим.
Значение с `$` заключите в одинарные кавычки в `.env`, чтобы Compose не подставлял
переменные. `.env` не отправляется в Git и не копируется в образ.
Вместо файла можно задать переменные в PowerShell; они имеют приоритет над `.env`:

```powershell
$env:MAX_BOT_TOKEN = Read-Host "Токен тестового бота MAX"
$env:MODERATOR_ACCESS_CODE = Read-Host "Секретный код модератора (от 12 символов)"
```

Проверка настройки и запуск:

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail 50 bot
```

`config --quiet` проверяет конфигурацию без вывода секретов. Обычный
`docker compose config` печатает подставленные значения — не публикуйте его вывод.
При первом запуске импортируется 85 событий, затем запускается бот.
Строка `catalog_import` в логах показывает итог импорта. Статус контейнера
`running` сам по себе не подтверждает правильность токена: проверьте `/start` в MAX.

Сервис называется `bot`, контейнер — `place-meeting`, локальный образ —
`place-meeting-bot:dev`. SQLite хранится в `/data/events_v2.db` в именованном
томе `place-meeting-data`. Compose создаёт его автоматически. Если такое имя
уже использовалось, будет подключена прежняя база; перед обновлением сделайте копию.
Если старый контейнер `place-meeting` создан через `docker run`, остановите и
удалите только контейнер, сохранив том, прежде чем переходить на Compose.

## Готовый Docker-образ и GHCR

**Публикация этой версии пока не подтверждена.** Локальная сборка проверена;
готовый путь публикации — `.github/workflows/publish-image.yml`.
После отправки изменений в `dev` GitHub Actions соберёт образ, проверит зависимости,
запустит тесты без сети и только после успеха отправит образ в GHCR.
Бот в Actions к MAX не подключается, его токен туда добавлять не нужно.

Планируемые имена:

- `ghcr.io/yarikk201/place-meeting:dev` — последняя успешная сборка `dev`.
- `ghcr.io/yarikk201/place-meeting:sha-<полный_SHA_коммита>` — конкретная сборка для сдачи.

Владельцу репозитория нужно разрешить GitHub Actions и публикацию пакетов
(`GITHUB_TOKEN` с `packages: write` уже указан в workflow), дождаться успешного
**Publish Docker image** и проверить пакет в GitHub → профиль → Packages.
Если workflow не запустился, откройте Actions → Publish Docker image → Run workflow
и выберите `dev` (кнопка ручного запуска может появиться только после попадания
workflow в основную ветку; автоматический запуск по push в `dev` этого не требует).
В настройках пакета установите **Public**, чтобы жюри могло скачать его без входа,
и укажите ссылку на пакет и точный SHA-тег в материалах сдачи.
Успех Actions не делает пакет публичным автоматически.

После подтверждённой публикации, из папки репозитория с настроенным `.env`:

```powershell
$env:BOT_IMAGE = "ghcr.io/yarikk201/place-meeting:dev"
docker compose pull bot
docker compose up -d --no-build --pull always
```

Для сдачи замените `dev` в переменной на реальный `sha-...` из успешного workflow.
Для возврата к локальной сборке удалите `BOT_IMAGE` из `.env` и выполните:

```powershell
Remove-Item Env:BOT_IMAGE -ErrorAction SilentlyContinue
docker compose up -d --build
```

Первый workflow публикует Linux/amd64, подходящий Docker Desktop на Windows x64.
ARM64 отдельно не проверен. До успешной публикации используйте сборку из исходников.

## Проверка функционала в MAX

Проводите проверку на своём тестовом боте и тестовых аккаунтах. Не загружайте
реальные документы и персональные сведения школьников в демонстрационную базу.

1. **Новый пользователь:** нажмите системную кнопку MAX «Начать». Должно появиться
   приветствие с выбором роли. Само открытие чата не всегда создаёт событие запуска;
   запасной способ — `/start`. Повторный запуск зарегистрированного пользователя
   открывает его меню, быстрые повторы не должны создавать одинаковые приветствия.
2. **Школьник:** заполните анкету, выберите интересы и навыки (от 1 до 10 каждого),
   опубликуйте её. Откройте каталог, фильтры «Онлайн», «Офлайн», «Без точной даты»,
   «Движение Первых» и «Волонтерство». Добавьте событие в избранное.
3. **Два школьника:** вторым аккаунтом опубликуйте анкету, отправьте заявку в друзья.
   Проверьте «Заявки» из главного меню с обеих сторон, принятие, разговор и сообщения.
   Жалоба прекращает дружбу/разговор и блокирует взаимодействие пары на 7 дней;
   повторная жалоба срок не продлевает, после истечения дружба сама не возвращается.
4. **Педагог:** отдельным аккаунтом выберите эту роль, подайте заявку на подтверждение
   (ФИО, место работы, должность, ссылка на документ). После одобрения создайте событие,
   проверьте предпросмотр, отправку на проверку, публикацию и правки. Даты вводятся
   как `ДД.ММ.ГГ`, `ДД.ММ.ГГ ЧЧ.ММ` или `ДД.ММ.ГГ - ДД.ММ.ГГ`; начало не в прошлом.
5. **Модератор:** отправьте `/moderator`, затем код из `MODERATOR_ACCESS_CODE`.
   Предварительно добавлять ID в SQLite не нужно. Проверьте подтверждение педагога,
   одобрение/отклонение события, скрытие и восстановление, жалобы. Пять неверных
   попыток входа блокируют ввод на 15 минут. Выход — `/moderator_logout`.
6. **Смена роли:** `/role` → «Написать модератору» → причина. До решения роль прежняя.
   Одобрение очищает данные прежней роли, включая её связи и авторские события;
   для обычной демонстрации используйте отдельные аккаунты вместо смены роли.
7. Перезапустите контейнер. Анкеты, заявки, каталог и избранное должны сохраниться.
   Проверьте кнопки уведомлений, возврат в меню и внешний вид карточек в клиенте MAX.

Доступные команды: `/start`, `/catalog`, `/filters`, `/people`, `/profile`, `/role`,
`/moderator`, `/moderator_logout`. Поиск людей показывает школьников.
Неизвестные slash-команды и пасхалки «Рокстар»/«Идея фикс» пока не реализованы.

## Тестирование без MAX

В окружении Python с установленными зависимостями достаточно одной команды:

```powershell
python -m unittest discover -s tests -q
```

После Docker-сборки, без токена и подключения к сети:

```powershell
docker run --rm --network none --entrypoint python place-meeting-bot:dev -m unittest discover -s tests -q
```

Проверены **83 теста**: навигация и повторы кнопок, первый запуск и `/start`,
смена роли, заявки, жалобы, модерация, даты, импорт и сохранность данных.
Тесты используют временную SQLite и имитацию MAX. Сообщения `callback_failed` и
`bot_start_failed` в тестовом выводе относятся к намеренно смоделированным сбоям;
итог должен быть `OK`. Реальная доставка и отображение клиентом MAX требуют
ручной проверки. Подробный результат инфраструктурной проверки —
[docs/verification.md](docs/verification.md).

### Запуск без Docker на Windows (Python 3.12)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
$env:EVENTS_DB = Join-Path $PWD "data\events_v2.db"
$env:MAX_BOT_TOKEN = Read-Host "Токен тестового бота MAX"
$env:MODERATOR_ACCESS_CODE = Read-Host "Код модератора (от 12 символов)"
.\.venv\Scripts\python.exe import_events.py
.\.venv\Scripts\python.exe bot.py
```

При прямом запуске Python файл `.env` автоматически не читается. Сначала остановите
Docker-экземпляр с тем же токеном. Для остановки Python нажмите Ctrl+C.

## Управление контейнером и обновление

Все команды выполняются в папке проекта:

```powershell
docker compose logs -f --tail 100 bot
docker compose restart bot
docker compose stop bot
docker compose start bot
docker compose down
```

`down` удаляет контейнер и сеть, но сохраняет данные. **Не используйте `down -v`
и не удаляйте `place-meeting-data`**: там вся пользовательская база.
Перезапуск не обновляет образ; после изменения файлов нужна пересборка.

Перед обновлением остановите бот и скопируйте базу:

```powershell
docker compose stop bot
New-Item -ItemType Directory -Force backups | Out-Null
docker cp place-meeting:/data/events_v2.db ./backups/events_v2.db
git switch dev
git pull --ff-only origin dev
docker compose up -d --build
```

Если использовали SQLite WAL вручную, сохраняйте также её `-wal`/`-shm` файлы.
Сначала проверяйте обновление на копии рабочего тома. Резервные копии и `.env`
не публикуйте. Для готового GHCR-образа обновление делается через `pull` и
`up -d --no-build --pull always`, как описано выше.

### Каталог и сохранение старой базы

`events.json` содержит 85 записей: 79 офлайн, 6 онлайн, 5 «Движения Первых»,
10 волонтёрских, 9 бессрочных и одну с открытой датой начала. Все теги, включая
две записи с пятью тегами, сохраняются. URL уникальны.
Даты: ISO-день/время, диапазоны с `-` или `—`, `бессрочно`, `с 01.01.2025`.
Прошедшие завершённые события не показываются; продолжающиеся остаются доступными.
Поэтому число карточек в интерфейсе зависит от текущей даты и фильтров.
Город неизвестной площадки не угадывается: сопоставления находятся в `filters.py`.

При старте импортёр проверяет весь JSON и выполняет обновление одной транзакцией.
Повторный импорт не создаёт дубликатов и не меняет ID существующих событий.
Список URL прежних 116 событий сохранён в `catalog_legacy_urls.json`; таблица
`imported_catalog` запоминает также новые импортированные URL. Исчезнувшие из JSON
импортированные события **скрываются**, но остаются в SQLite вместе с избранным.
Неизвестные записи не удаляются. События с владельцем-педагогом или историей
педагогических заявок защищены от перезаписи и скрытия даже при совпадении URL.
Такие конфликты учитываются в `protected` в итоговой строке импорта.

На прежней стандартной базе остаются 139 строк: 85 текущих и 54 скрытых старых.
Авторские события и другие записи увеличивают это число. Скрытие модератором
сохраняется. Если скрытый URL снова добавлен в JSON, восстановите событие через
модератора: импортёр сам не отменяет скрытие. Избранное станет доступно снова.

### HTTPS и возможные ошибки

Контейнер содержит системные `ca-certificates`; TLS проверяется стандартными
средствами Python/aiohttp. Локальные `root.cer`/`sub.cer` больше автоматически
не включаются в образ. Если организация использует свой HTTPS-прокси,
администратор должен настроить доверенный CA; отключать проверку TLS нельзя.
Для сборки за таким прокси Dockerfile поддерживает необязательный BuildKit-секрет
`build_ca` с PEM-набором доверенных CA. Он нужен только `pip` во время сборки,
не сохраняется в образе и не меняет доверие работающего бота.

При перезапусках контейнера проверьте логи, токен, код модератора и доступ к MAX.
Если экран не появился после сетевого сбоя, используйте `/start`.
Уведомления при неопределённом результате отправки не повторяются автоматически.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `bot.py` | Команды, события MAX, кнопки, экраны и уведомления |
| `catalog.py`, `import_events.py` | SQLite и безопасное обновление каталога |
| `events.json`, `catalog_legacy_urls.json` | Текущий каталог и URL для перехода со старого |
| `filters.py`, `event_tags.py`, `presentation.py` | Фильтры, теги, даты и оформление карточек |
| `profiles.py`, `taxonomy.py`, `people.py` | Анкеты, интересы/навыки, поиск школьников |
| `social.py`, `direct_messages.py`, `favorites.py` | Друзья, сообщения, жалобы, избранное |
| `teacher_events.py`, `role_requests.py` | Проверка педагогов, событий и смены роли |
| `Dockerfile`, `.dockerignore`, `compose.yaml` | Сборка и запуск контейнера |
| `.env.example`, `requirements.txt`, `constraints.txt` | Образец настройки и версии библиотек |
| `.github/workflows/publish-image.yml` | Проверка и публикация образа в GHCR |
| `tests/`, `docs/verification.md` | Автотесты и результат проверки перед сдачей |

## Перед сдачей и слиянием dev → main

Команда проверяет изменения, миграцию на копии своей базы и сценарии в MAX.
Для жюри нужны исходники, этот README, зависимости, Dockerfile/Compose и доступный
образ: завершите публикацию GHCR и проверьте скачивание без авторизации.
Укажите в заявке ссылку на репозиторий, пакет, SHA-тег и адрес демонстрационного бота;
код модератора передавайте проверяющим отдельно. Текст пункта 9.7 целиком здесь
не приложен: остальные материалы сверяйте с оригиналом Положения.
По `AGENTS.md` и пункту 9.5 команда должна самостоятельно проверить и понимать
вклад, сделанный с помощью ИИ, и уточнить у организаторов допустимость его использования.
Слияние в `main` выполняет команда после проверки.
