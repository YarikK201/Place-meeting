# Место встречи

Бот для MAX, который помогает школьникам искать мероприятия, знакомиться и собирать команды. Педагоги могут предлагать свои мероприятия, а модераторы проверяют заявки.

Проект написан на **Python 3.12**. Данные хранятся в **SQLite**, бот запускается через **Docker**. Весь код разделён на небольшие файлы, чтобы было легче разобраться.

## Что уже умеет бот

- Показывает каталог мероприятий с фильтрами и избранным.
- Создаёт анкеты школьников и педагогов: город, возраст, интересы и навыки.
- Ищет людей по возрасту, интересам и навыкам.
- Позволяет публиковать и скрывать анкеты.
- Отправляет заявки в друзья, принимает и отклоняет их.
- Передаёт текстовые сообщения и ответы через бота.
- Принимает жалобы и умеет блокировать пользователей.
- Проверяет статус педагога и новые мероприятия через модератора.
- Меняет роль только после одобрения модератора. При одобрении данные старой роли очищаются.

Большая часть действий доступна через кнопки. Текст нужно вводить только в анкету, при написании сообщения, указании ссылки и подобных случаях.

## Запуск на Windows

Нужен запущенный **Docker Desktop**. Выполняем команды в PowerShell из папки проекта:

```powershell
cd "C:\Users\MSI\Place-meeting"
docker build -t place-meeting-bot .
```

Теперь задаём токен своего бота MAX и код модератора. Код должен быть длинным (от 12 символов), он **не должен совпадать с токеном бота**:

```powershell
$env:MAX_BOT_TOKEN = Read-Host "Токен бота MAX"
$env:MODERATOR_ACCESS_CODE = Read-Host "Секретный код модератора"
```

Запуск:

```powershell
docker rm -f place-meeting
docker run -d --name place-meeting --restart unless-stopped `
  -v place-meeting-data:/data `
  -e MAX_BOT_TOKEN `
  -e MODERATOR_ACCESS_CODE `
  place-meeting-bot
```

Если это первый запуск и контейнера ещё нет, ошибку от `docker rm` можно пропустить.

Проверить, что контейнер работает:

```powershell
docker ps
docker logs --tail 30 place-meeting
```

Если раньше для доступа к MAX требовались сертификаты `root.cer` и `sub.cer`, положите их рядом с Dockerfile **перед сборкой**. Dockerfile установит их автоматически.

### Как обновить бот

1. Сохраняем резервную копию проекта и базы.
2. Заменяем Python-файлы новой версией.
3. Повторяем `docker build -t place-meeting-bot .`.
4. Пересоздаём контейнер командами выше.

**Не удаляйте том `place-meeting-data`.** В нём лежит `/data/events_v2.db` — анкеты, заявки, избранное, права модераторов и другие данные.

Для копии базы перед обновлением (пока контейнер существует):

```powershell
docker cp place-meeting:/data/events_v2.db .\events_v2_backup.db
```

## Как пользоваться

1. `/start` — первый выбор роли, затем главное меню. При повторном запуске можно попросить сменить роль.
2. `/catalog` — мероприятия, `/filters` — фильтры.
3. `/people` — поиск участников, `/profile` — своя анкета.
4. `/moderator` — вход в модерацию по коду. `/moderator_logout` — выход.
5. Педагог проходит проверку отдельно; сама роль не даёт права публиковать мероприятия без подтверждения.

У модератора есть проверка педагогов, мероприятий, жалоб и заявок на смену роли. При смене роли старая анкета, контакты, заявки и связанные с ролью данные удаляются.

## Что важно знать

- Бот общается с MAX через Long Polling, поэтому Docker должен оставаться запущенным.
- Короткий кэш ускоряет каталог. Для этого не нужны отдельные сервисы.
- Код модератора вводится в личном чате. Не отправляйте его в группы и не публикуйте в GitHub. Если код узнает посторонний, он тоже сможет получить доступ.
- При создании или обновлении мероприятий исходные данные берутся из `events.json` и SQLite. При повторном импорте не должно появляться дубликатов.
- **Работу в реальном MAX нужно проверять отдельно.** Корректный синтаксис Python сам по себе не гарантирует, что сервер MAX примет все запросы.
- Для запуска с реальными школьниками потребуется отдельная проверка безопасности, доступа к модерации и обработки жалоб.

## Удаление старых файлов после распаковки

Архив содержит только нужные файлы, но распаковка с `-Force` **не удаляет** файлы старой версии. Чтобы очистить папку проекта, выполните:

```powershell
Remove-Item test_local.py, test_new_features.py, test_role_change.py, test_speed.py, test_turbo.py -ErrorAction SilentlyContinue
Remove-Item README_NEW_SPEC.md, README_ROLE_CHANGE.md, README_SPEED.md, README_TURBO.md -ErrorAction SilentlyContinue
```

Резервные копии `bot_backup.py`, `bot_before_*.py` и подобные файлы можно удалить вручную, если они больше не нужны. Не удаляйте оригинальные `root.cer`, `sub.cer` и базу данных.

## Как сохранить изменения в GitHub

Проверьте файлы перед коммитом: в репозиторий **не должны попадать** токены, сертификаты, резервные копии и SQLite-базы.

```powershell
git status
git add bot.py catalog.py events.json import_events.py filters.py favorites.py profiles.py taxonomy.py people.py social.py direct_messages.py teacher_events.py role_requests.py requirements.txt Dockerfile .dockerignore .gitignore README.md
git add -u
git status
git commit -m "refactor: clean up bot and simplify project"
git push origin dev
```

`git add -u` зафиксирует удаления старых тестов и README, если они ранее отслеживались Git. Перед коммитом проверьте `git status`, чтобы не включить посторонние изменения.
