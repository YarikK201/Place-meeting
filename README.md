# Место встречи

«Место встречи» — бот в MAX для школьников и педагогов Кузбасса с возможностью
масштабирования на всю Россию. Он помогает найти интересное занятие и компанию 
для участия. Мероприятия, знакомства и общение собраны в одном чате.

Школьники могут создать анкету, искать мероприятия, сохранять избранное
и добавлять друзей. Педагоги предлагают события. Модераторы проверяют
заявки, публикации и жалобы.

## Как запустить бота на Windows

### 1. Установите Docker Desktop

Скачайте [Docker Desktop с официального сайта](https://docs.docker.com/desktop/setup/install/windows-install/).
Следуйте инструкции установки, включая настройку WSL 2. Затем откройте
Docker Desktop и дождитесь готовности. Нужен режим Linux containers.

### 2. Скачайте проект

Откройте [ветку main на GitHub](https://github.com/YarikK201/Place-meeting).
Убедитесь, что над списком файлов выбрана **main**. Нажмите **Code → Download ZIP**.
Распакуйте архив. Откройте папку, в которой находятся `compose.yaml` и `Dockerfile`.

### 3. Откройте PowerShell

В адресной строке этой папки в Проводнике напишите `powershell` и нажмите Enter.
Все следующие команды выполняйте в открывшемся окне.

### 4. Настройте токен и код модератора

Для своего запуска нужен токен собственного тестового бота MAX. Получите его
через платформу MAX по [официальной инструкции](https://dev.max.ru/docs-api).
Не публикуйте токен в GitHub и не отправляйте его в общий чат.

Выполните по очереди и введите запрошенные значения:

```powershell
$env:MAX_BOT_TOKEN = Read-Host "Введите токен своего MAX-бота"
$env:MODERATOR_ACCESS_CODE = Read-Host "Придумайте секретный код модератора: минимум 12 символов"
```

Код модератора придумайте сами. Он понадобится для входа в панель проверки заявок.
Эти настройки действуют только в текущем окне PowerShell.

Чтобы сохранить настройки между открытиями окна, можно вместо команд создать
локальный файл `.env` из образца и заменить в нём значения:

```powershell
Copy-Item .env.example .env
notepad .env
```

Сохраните файл под именем `.env`, без добавления `.txt`. Не передавайте его другим.
Значение с символом `$` заключите в одинарные кавычки. Переменные из PowerShell
имеют приоритет над одноимёнными значениями из файла.

### 5. Соберите и запустите

После настройки обеих переменных выполните:

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Первая сборка может занять несколько минут. Docker загрузит нужные компоненты,
импортирует каталог из 85 мероприятий и запустит бот. В списке контейнеров
должен появиться `place-meeting` со статусом `Up`.

### 6. Откройте бота в MAX

Откройте **своего бота, чей токен вы указали**, и нажмите «Начать» или отправьте
`/start`. Появится приветствие с кнопками выбора роли. Зарегистрированный
пользователь увидит своё главное меню.

На один токен должен работать только один экземпляр бота. Перед запуском
остановите другие экземпляры с тем же токеном. Статус `Up` подтверждает запуск
контейнера; ответ на `/start` подтверждает связь с MAX.

### Альтернатива: готовый образ из GHCR

Образ — уже собранное приложение. После настройки переменных на шаге 4
в той же папке проекта выполните:

```powershell
$env:BOT_IMAGE = "ghcr.io/yarikk201/place-meeting:dev"
docker compose pull bot
docker compose up -d --no-build --pull always
```

Этот способ требует доступного опубликованного пакета в
[GitHub Packages](https://github.com/YarikK201?tab=packages&repo_name=Place-meeting).
Если скачивание недоступно, используйте сборку из исходников на шаге 5.
Для возврата к ней удалите `BOT_IMAGE` из `.env`, если добавляли, и выполните:

```powershell
Remove-Item Env:BOT_IMAGE -ErrorAction SilentlyContinue
docker compose up -d --build
```

## Как проверить функции

Для демонстрации используйте тестовые аккаунты и данные. Не загружайте реальные
документы школьников. Для общения нужны два аккаунта MAX.

| Сценарий | Что сделать |
| --- | --- |
| Школьник | Выберите роль, заполните и опубликуйте анкету. Откройте мероприятия, настройте фильтры и добавьте событие в избранное. |
| Общение | Вторым аккаунтом создайте анкету. Найдите его через поиск людей, отправьте заявку в друзья. Проверьте раздел «Заявки», примите заявку и отправьте сообщение. |
| Педагог | Отдельным аккаунтом выберите роль педагога. Подайте данные на подтверждение. После одобрения создайте мероприятие и отправьте его модератору. |
| Модератор | Отправьте `/moderator`, затем код из `MODERATOR_ACCESS_CODE`. Проверьте заявки педагогов, публикации, скрытие мероприятий и жалобы. Выход — `/moderator_logout`. |

`/start` возвращает в главное меню. Также `/start` можно использовать
при зависаниях - тогда бот автоматически возвращается на главный экран.
`/role` открывает заявку на смену роли.
Одобрение смены роли удаляет данные прежней роли, поэтому для демонстрации
школьника и педагога удобнее использовать разные аккаунты.

## Как остановить и снова включить бота

В папке проекта выполните:

```powershell
docker compose down
```

Для повторного запуска:

```powershell
docker compose up -d
```

Если открыли новое окно PowerShell и не используете `.env`, сначала снова
задайте токен и код модератора. Обычная остановка сохраняет анкеты, заявки
и избранное в томе `place-meeting-data`. **Не используйте `docker compose down -v`
и не удаляйте этот том:** это удалит базу.

Перед обновлением остановите бот и сохраните копию базы:

```powershell
docker compose stop bot
docker cp place-meeting:/data/events_v2.db ./events-backup.db
```

Не публикуйте резервную копию. После обновления исходников повторите
`docker compose up -d --build`. Для готового образа повторите команды `pull`
и `up` из раздела GHCR. Если уже существует контейнер `place-meeting`,
созданный вручную вне Compose, сначала остановите и удалите его, сохранив том.

## Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| Docker не запускается | Откройте Docker Desktop. Проверьте установку WSL 2 и режим Linux containers по официальной инструкции. |
| Не задан токен или код | Повторите шаг 4 в текущем окне PowerShell либо заполните `.env`. Код должен содержать минимум 12 символов. |
| Бот не отвечает | Проверьте `docker compose ps`, правильность токена и отсутствие второго экземпляра. Отправьте `/start`. |
| Ошибка подключения к MAX | Проверьте интернет и доступ к MAX. При ошибке сертификатов обратитесь к администратору сети; не отключайте проверку TLS. |
| Нужны подробности ошибки | Выполните `docker compose logs --tail 100 bot`. Не публикуйте секреты и личные данные из диагностического вывода. |

## Техническая информация

Python 3.12, MAX API и `maxapi==1.2.3`, SQLite, Docker и Docker Compose V2.
Бот получает события через Long Polling. Входящие порты и публичный домен не нужны.
SQLite находится в `/data/events_v2.db`. HTTPS использует системные сертификаты
с проверкой TLS.

| Файлы | Назначение |
| --- | --- |
| `bot.py` | Команды MAX, кнопки и навигация |
| `profiles.py`, `people.py`, `taxonomy.py` | Анкеты и поиск людей |
| `social.py`, `direct_messages.py`, `favorites.py` | Друзья, общение и избранное |
| `teacher_events.py`, `role_requests.py` | Модерация и смена роли |
| `catalog.py`, `import_events.py` | SQLite и загрузка каталога |
| `events.json`, `catalog_legacy_urls.json` | Текущие мероприятия и совместимость со старым каталогом |
| `filters.py`, `event_tags.py`, `presentation.py` | Фильтры, теги и оформление карточек |
| `Dockerfile`, `compose.yaml` | Сборка и запуск приложения |
| `requirements.txt`, `constraints.txt` | Библиотеки Python и закреплённые версии |
| `.env.example` | Образец локальных настроек |
| `.github/workflows/publish-image.yml` | Технические проверки и публикация образа в GHCR |

Повторный импорт не создаёт дубликатов. Устаревшие записи прежнего каталога
скрываются с сохранением ID и избранного. Мероприятия педагогов защищены от
перезаписи импортом. Завершённые события скрывает фильтр по текущей дате.
