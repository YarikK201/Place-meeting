## Как проверялся запуск

Для инфраструктурного smoke-теста использованы отдельные контейнер
`place-meeting-hackathon-check` и том `place-meeting-hackathon-check-data`.
Временный Compose override задавал `network_mode: none` и фиктивные переменные.
Через временный `sitecustomize.py` подменялся только `Dispatcher.start_polling`:
он записывал номер запуска в тестовую SQLite и ожидал остановки.
Обычный CMD образа (`import_events.py`, затем `bot.py`) не заменялся.
Проверялись готовность после инициализации, количество событий и сохранённое
избранное после `docker restart` и `compose up --force-recreate`.
Тестовые контейнер и том после проверки удалены; рабочий том не использовался.

Для сборки в облаке понадобились настройки инфраструктурного HTTPS-прокси:
`--network host`, `--add-host proxy:<адрес прокси>`, build args `HTTP_PROXY`/
`HTTPS_PROXY` и BuildKit secret `build_ca` с доверенными CA окружения.
Проверка TLS оставалась включённой. Эти параметры не нужны для обычного
Docker Desktop с прямым доступом к реестрам и PyPI.
